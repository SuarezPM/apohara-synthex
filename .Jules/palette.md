## 2026-05-29 - Adding Form Usability to Live Console\n**Learning:** The live console in public/index.html was not wrapped in a formal <form> tag, which meant natural keyboard navigation (pressing Enter to submit) didn't work. The input also lacked guidance (placeholder) and validation (empty submissions were allowed), leading to a frustrating experience. Adding aria-busy to the submit button provides critical screen-reader feedback during the long-running async pipeline execution.\n**Action:** When working with custom JS-driven "forms" that don't use standard HTML <form> submission, always ensure keyboard events (keydown Enter) are manually wired to trigger the primary action, and manage aria-busy state on buttons for async operations.

## 2026-06-25 - Managing Async Visual States for PDF Downloads
**Learning:** During PDF generation downloads, users had no indication that a request was in flight because the button remained active. Standard JS forms without native submit behaviors must manually communicate state for all async operations to prevent duplicate clicks and user confusion.
**Action:** Always wrap file generation or blob fetching logic in a `try...finally` block. During execution, temporarily set `disabled=true` and `aria-busy="true"` on the trigger button, and update its text (while safely caching and restoring the original HTML to preserve inline SVGs). Additionally, explicitly adjust CSS for `:disabled` states, avoiding `hover` interference using `:hover:not(:disabled)`.
