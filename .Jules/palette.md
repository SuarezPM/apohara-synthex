## 2026-05-29 - Adding Form Usability to Live Console\n**Learning:** The live console in public/index.html was not wrapped in a formal <form> tag, which meant natural keyboard navigation (pressing Enter to submit) didn't work. The input also lacked guidance (placeholder) and validation (empty submissions were allowed), leading to a frustrating experience. Adding aria-busy to the submit button provides critical screen-reader feedback during the long-running async pipeline execution.\n**Action:** When working with custom JS-driven "forms" that don't use standard HTML <form> submission, always ensure keyboard events (keydown Enter) are manually wired to trigger the primary action, and manage aria-busy state on buttons for async operations.

## 2026-05-30 - Adding Loading Feedback to File Generation
**Learning:** During the PDF Evidence Report generation via the `#dl` download button, the application would hang without giving any visual feedback to the user, making it seem like the interface had frozen. Furthermore, standard button hover effects inappropriately continued to apply to buttons when they were in a disabled state, creating confusion about interactivity.
**Action:** Always explicitly handle loading states for async file downloads by caching the button's initial `innerHTML`, switching it to a disabled/aria-busy state with temporary feedback text (e.g., "Generating PDF..."), and ensuring pseudo-class hover effects use `:hover:not(:disabled)` to properly represent interactive state. Wrap all logic in a `try...finally` block to guarantee state restoration regardless of success or failure.
