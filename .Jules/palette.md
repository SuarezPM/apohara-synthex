## 2026-05-29 - Adding Form Usability to Live Console\n**Learning:** The live console in public/index.html was not wrapped in a formal <form> tag, which meant natural keyboard navigation (pressing Enter to submit) didn't work. The input also lacked guidance (placeholder) and validation (empty submissions were allowed), leading to a frustrating experience. Adding aria-busy to the submit button provides critical screen-reader feedback during the long-running async pipeline execution.\n**Action:** When working with custom JS-driven "forms" that don't use standard HTML <form> submission, always ensure keyboard events (keydown Enter) are manually wired to trigger the primary action, and manage aria-busy state on buttons for async operations.
## 2026-06-15 - Managing Async State and Scoping Hover in Vanilla JS UI
**Learning:** The "Download Evidence Report" button lacked visual feedback while waiting for the async PDF generation to complete, which could lead to multiple clicks and confusion. Implementing a loading state requires disabling the button and modifying text, but an important realization is that existing CSS hover states (`:hover`) will often override or persist visually even when the element is `disabled` in HTML unless explicitly excluded (e.g., `:hover:not(:disabled)`).
**Action:** When adding async loading states to vanilla frontend buttons via JavaScript (disabling, setting aria-busy, updating text in try/finally blocks), always check the corresponding CSS and ensure that any `:hover` pseudo-classes explicitly exclude the `:disabled` state to prevent confusing visual interactions while processing.
