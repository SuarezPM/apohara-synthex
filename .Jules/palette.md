## 2026-05-29 - Adding Form Usability to Live Console\n**Learning:** The live console in public/index.html was not wrapped in a formal <form> tag, which meant natural keyboard navigation (pressing Enter to submit) didn't work. The input also lacked guidance (placeholder) and validation (empty submissions were allowed), leading to a frustrating experience. Adding aria-busy to the submit button provides critical screen-reader feedback during the long-running async pipeline execution.\n**Action:** When working with custom JS-driven "forms" that don't use standard HTML <form> submission, always ensure keyboard events (keydown Enter) are manually wired to trigger the primary action, and manage aria-busy state on buttons for async operations.
## 2026-06-04 - [Inline validation & Async Loading states]
**Learning:** For async pipeline operations that take some time, combining a visual SVG spinner inside the submit button alongside clear text ("Running pipeline...") greatly reassures the user. Additionally, form errors handled only with a brief UI animation (like a CSS "shake") can be easily missed or ambiguous; introducing an explicit `aria-errormessage` and an `aria-live="polite"` feedback element ensures both screen reader users and visual users understand exactly what correction is needed.
**Action:** Always provide explicit error messages tied to their respective inputs via ARIA rather than relying purely on CSS animations for validation cues. Always pair disabled states for async submit buttons with clear visual and textual loading feedback.
